# tdesk · Rust Stock Trading Terminal (Paper / Simulated)

> ⚠️ **This project is a local paper-trading / educational demo system. Market data is generated by a deterministic algorithm; it connects to no broker or exchange, moves no real money, and is not investment advice.**

A desktop stock-trading terminal written in **Rust + egui/eframe**: a complete offline loop of price charts (K-line), order entry & cancellation, matching & settlement, risk control, position P&L, and strategy backtesting — all runnable without a network.

## Quick Start

```bash
# Requires Rust 1.80+ (verified on 1.99.1)
cargo run -p tdesk-app          # open the desktop window
cargo run -p tdesk-cli          # headless end-to-end demo + assertions + perf benchmark
cargo test --workspace          # all unit / integration / UI smoke tests
```

On macOS the system `Arial Unicode.ttf` is auto-loaded on first launch for Chinese text — no extra setup needed.

## Features

| Module | Contents |
| --- | --- |
| Multi-market | Switch between A-share / US / HK: up/down colors, T+0/T+1, price limits, lot sizes, and fees are all driven by `MarketRules` |
| Market data | 14 instruments, deterministic synthetic daily K-bars and tick-by-tick playback; K-line / volume / MA5 / MA20 / crosshair OHLC tooltip |
| Trading | Limit orders, market orders (IOC), price–time-priority matching, partial fills, cancellation, self-trade prevention, trade prints |
| Risk control | Quantity / lot / price / price-limit / available-cash / sellable-qty / single-order concentration checks; rejections leave the account with zero side effects |
| Account | Cash, position cost, T+1 lock & release, unrealized P&L, realized P&L, fees, total-equity identity |
| Backtest | `Strategy` trait + SMA(5,20) golden/death cross; signal on T-day close, fill on T+1 open; equity curve, return, drawdown, win-rate, Sharpe |
| Programmatic strategies | Twin `Strategy`/`LiveStrategy` traits, isomorphic: **dual-MA golden/death cross**, **N-day breakout (momentum)**, **mean reversion (Bollinger)**; one codebase both backtests and drives live paper orders |
| Auto-trading loop | `Broker` port + `LiveTrader`: quotes → strategy → sizing → order → settlement; paper (`PaperBroker`) and live (`LiveBroker` skeleton) are isomorphic; CLI demo runs a 3000-tick auto buy/sell loop |
| Engineering | Layered Cargo workspace, `cargo clippy` warning-free, UI renders and is testable in headless environments |

## Architecture

```
crates/tdesk-app   egui desktop terminal (presentation layer)
crates/tdesk-cli   headless demo & benchmark (presentation layer)
crates/tdesk-data  MarketDataSource → SyntheticSource / CsvSource (adapter layer)
crates/tdesk-core  MarketRules / MatchingEngine / Account / risk / backtest
                    + Broker(PaperBroker/LiveBroker) / LiveTrader / strategies (domain layer, zero external deps)
```

Dependencies flow strictly one-way: `app|cli → data → core`. Prices use the integer `Price` (smallest tick), and money uses `Money` (smallest currency unit); the whole pipeline has no floating-point accounting drift.

## Common Operations

| What you want to do | How to do it |
| --- | --- |
| Switch market | Top bar `A股·沪深 / 美股 / 港股` (resets the simulated account) |
| Switch instrument | Click a code in the left watchlist |
| Place an order | Right panel: pick buy/sell, limit/market, enter price & qty, or click `25% / 50% / 全部` to auto-size, then submit |
| Cancel an order | Bottom "委托" (Orders) tab → "撤单" (Cancel) on the right of an active order |
| See T+1 | Bottom "持仓" (Positions) page `可卖 / T+1锁定`; click top-bar "推进一日" (Advance Day) to release |
| Run a backtest | Bottom "回测" (Backtest) page → `运行 SMA(5,20) 回测` |

## Connecting a Real Broker (Live Trading)

This project abstracts "order placement" into a **`Broker` trait** and wraps the original simulated matching engine as `PaperBroker`. This means the **trading logic (strategies, risk control, sizing, settlement) is fully reused between paper and live** — connecting a real broker only requires adding one more `impl Broker`.

> ⚠️ **About the "East Money Securities API":** East Money Securities **does not offer an official trading API for retail investors**. The only unofficial paths to programmatic order placement at brokers like East Money / Tonghuashun / GF are: quantitative-platform gateways (QMT / Ptrade / 掘金), client automation (easytrader-style reverse protocol or UI scripting), or reverse-engineered web quote/trade interfaces. The latter two **violate broker user agreements, carry account-ban and compliance risk, and involve real money**.
>
> Therefore `LiveBroker` is currently a **deliberately empty skeleton**: any `submit` explicitly returns `BrokerError::NotConfigured`. Rolling out a real channel must go through: ① confirm a compliant, usable channel and obtain credentials; ② credential isolation (env vars / secret store, never in the repo); ③ audit logging and rate limiting; ④ run `PaperBroker` end-to-end first, then switch to `LiveBroker`. This step is physically isolated from the paper system and is recommended as a separate task to evaluate.

The auto-trading that runs directly today is the **paper loop**: section 7 of `cargo run -p tdesk-cli` drives `SyntheticSource` quotes + `PaperBroker` + `DualMaStrategy`, automatically buying/selling over 3000 ticks on the dual-MA golden/death cross.

## Known Simplifications

HK price ladder is flattened to 0.01; market orders are treated as IOC; no dividends/splits, securities lending, call auction, real market data, or live interfaces. See section 8 of the requirements doc for details.
